# Mag Life — 日常に、余白と出会いを。

React + Vite + TypeScript で動く、雑誌の視点で空き時間にお出かけを提案する日本語のカレンダーデモです。

## セットアップ

Node.js 24 を推奨します（アプリ本体は20.19以降の20系、または22.12以降でビルド可能。`npm test` はTypeScriptを直接実行できるNode.js 22.18以降が必要です）。

```sh
npm ci
npm run dev
```

http://localhost:5173/magazine-linked-calendar-app/ を開いてください。

## できること

- **カレンダー**：最初に日表示の縦型タイムラインを表示。00:00–24:00の時間軸、開始・終了時刻に比例するブロック、時間ごとの線、30秒ごとに更新する現在時刻ライン。重複する保存済み予定は横並びにします。日・週・月の切り替え、前後移動、今日への復帰、追加・編集・削除も維持しています。月の日付タップは日表示に移動し、週表示では7日間と選択日のタイムラインを確認できます。
- **カラフルな予定**：白い土台に、仕事はブルー、デートはピンク、グルメはオレンジ、美容はパープル、旅行はターコイズ、趣味はイエロー、アウトドアはグリーン。旧カテゴリーとデータもそのまま利用できます。
- **空き時間提案**：選択日の09:00–22:00にある45分以上の空き時間を検出。既存予定の前後と提案間に10分の移動目安を確保し、所要時間・デモ営業時間に合う体験だけを最大3件仮配置します。短い余白には短時間の体験を優先。淡色背景・破線枠・雑誌アイコンとラベルで区別し、文字は薄くしません。予定の編集・削除時に再計算します。**実際のAI生成ではなく、同梱データによるルールベースのデモ推薦です。**
- **操作できるカード**：仮提案をタップするとカードの詳細を表示。指・マウスの横移動に追従して回転し、右で保存、左でスキップ。320msで画面外に加速し、背面の次のカードが現れます。閾値に届かない場合は戻り、縦操作はスクロールに任せます。ボタンでも同じ演出を実行。「予定に追加」は日時確認フォームを開き、確定時に重複を再確認します。保存だけでは登録されません。日ごとのスキップと「見つける」のスキップは再読み込み後も維持し、「もう一度見る」で解除できます。
- **予定の詳細**：カテゴリー色・タイトル・日付・時間・場所・メモと、A LITTLE INSPIRATIONを表示。関連する架空雑誌の表紙から記事・体験・PR商品を開けます。PR商品には明確な広告表記・専用イラスト・架空ブランド・説明・価格・詳細・お気に入り保存を用意。商品のお気に入りは予定と独立しています。
- **記事・スポット**：18件のオリジナルの架空記事を収録。日時を持つ体験、商品、読むだけの記事を区別。体験だけを仮配置し、商品・読みものは「見つける」や予定詳細で閲覧・保存します。読みもの・商品に予定登録ボタンはありません。
- **6つの架空雑誌**：HOMME DAYS（メンズライフスタイル）、ROAMÉ DAYS（旅行）、LUMIÈRE ME（女性の美容）、FERN & FAR（アウトドア）、SHIFT & SILK（働く女性のファッション）、SAJI / TABLE（食）。「見つける」の表紙棚は横スクロール・タップに対応します。実在の雑誌ブランドは使用していません。
- **モバイル**：白いキャンバス・コンパクトなロゴ・固定ボトムナビで、カレンダー／見つける／一日プラン／お気に入りを切り替え。今日を鮮やかな赤で強調し、月のセルには折り返し可能な予定ラベルを表示します。
- **一日プラン**：11:00カフェ → 13:00ギャラリー → 15:30ショッピング → 18:00ディナー。各スポットから記事を開けます。日付を選び、4件をまとめて追加できます。
- **広告**：Sponsored Recommendation / Calendar Native Ads / Editorial Sponsored Story を収録。カード・記事・追加された広告の予定にもPRを明示。読むだけでは予定に追加されません。
- **モーション**：カードの表示・タップ・ドラッグ、お気に入り、広告バナーのホバーに対応。`prefers-reduced-motion` に従い動きを抑制します。

## 保存・予定の重複

予定・お気に入り・スキップを、このブラウザの `localStorage`（`mag-life-v1`）に保存します。同じブラウザ・同じオリジンで再度開くと復元されます。旧形式の予定・お気に入りは変更・削除せず復元し、任意の `skipped` フィールドだけを追加しています。仮提案は予定データに保存せず、毎回算出します。外部送信・アカウント認証・端末間同期はありません。保存失敗や不正な保存データは画面に通知します。

追加・編集時には時間の重複を確認します。一日プランは既存予定と重なる、または同じスポットが登録済みの場合、**1件も追加せず**日付の変更・予定の調整を案内します。空き時間への追加後は提案を再計算します。

起動時にデモ予定を前後約7週間分生成します。予定のない日も自由に追加できます。ブラウザのサイトデータを消去するとデモ初期状態に戻ります。

## 検証

```sh
npm run lint
npm test
npm run build
npm run preview -- --host 0.0.0.0
```

`build` は TypeScript の型チェックと `dist/` への本番ビルドです。19件のドメインテストで空き時間の45分境界、移動余白、仮提案の件数・非重複・営業時間、重複予定のレーン、編集・削除後の再計算、分類、旧形式データの保持、商品保存、スキップの永続化、一日プラン、保存失敗を確認します。

UIの確認手順：PCとスマートフォン幅で、月→日・週の日付選択、仮提案の左右ドラッグとボタン、短いドラッグの復帰、縦スクロール、保存後の再読み込み、日時確認・重複拒否・正式追加、編集・削除後の再配置、表紙→記事、PR商品詳細・保存を確認します。実機のiOS Safari / Android Chromeでのタッチ感は公開前にも確認してください。

## GitHub Pages

公開先： https://otoufutarou.github.io/magazine-linked-calendar-app/

Vite の `base` は `/magazine-linked-calendar-app/`。画像も `import.meta.env.BASE_URL` から参照し、サブパスに対応します。画面はアプリ内の状態で切り替わるため、サーバーのルート設定やSPA用404ページは不要です。画像・記事は同梱しており、外部API・外部フォントサービスなしで動作します。

PRでは **Check Mag Life** がlint・テスト・ビルドを実行します。`main` へのマージ後は **Deploy to GitHub Pages** が同じ検証を行い、成功した `dist/` を公開します。Settings → Pages → Source は **GitHub Actions** を選択してください。

## デモの範囲・素材

ユーザー・雑誌名・記事・スポット・商品・広告案件はすべて架空です。記事本文・商品イラストはオリジナルで、実在の記事の転載はありません。AI API・雑誌アーカイブへの接続、予約・購入・実際の広告配信・実店舗への送客は行いません。位置情報・交通経路・祝日・リアルタイムの営業時間には連動していません。推薦の移動時間は前後各10分の固定デモ目安で、実際の移動可能性を保証しません。一日プランは従来どおり移動・休憩を含むモデルプランです。

写真は店舗・展示を表すイメージです。一部は複数の記事で共用しています。同梱した写真の出典とライセンス表記は `public/images/THIRD-PARTY-NOTICES.txt` を参照してください。
